Build **Woodoku** as a new top-level game in `client-games`, beside Orbital Dodger and Space Golf (its own registry entry and route; not a prototype under `/game/prototypes`). Add an OpenSpec spec `openspec/specs/games-woodoku/` (`**App**: games`).

The ticket holds everything: `docs/tickets/open/games-wood-block-puzzle-woodoku-style-drag-polyomino-pieces-fwsk.md`. It has the human's words verbatim, the research, and the proposed rules:
- 9x9 board on a brown wood theme; rows, columns and 3x3 boxes clear at the same time; nothing falls.
- 3-piece tray, no rotation, refilled once all 3 are placed; game over when no piece fits anywhere.
- Scoring (proposed, not documented anywhere): +1 per cell placed, plus combo and streak bonuses. Show the best score.
- Phone portrait, touch drag:
  - the dragged piece rides above the finger
  - snap to the grid, with a ghost preview
  - highlight what a drop would clear before it lands
  - an invalid drop springs back to the tray

The human confirmed the game is Woodoku ("I think it is Woodoku. The grid felt larger than that but it looks right"), so keep the board size an easily changed constant.

Out of scope: undo, power-ups, rotation, levels and daily modes. If Phaser is used, keep it externalised (CLAUDE.md). Check: `npx vitest run client-games && npm run build:games`. Put the game logic (placement, clears, scoring, game over) in pure modules with tests.
